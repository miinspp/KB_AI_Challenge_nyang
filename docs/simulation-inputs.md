# 금융 시뮬레이션 입력 명세

## 현재 화면에서 계산 엔진으로 전달되는 값

| 구분 | 필드 | 현재 출처 | 시뮬레이션 반영 |
| --- | --- | --- | --- |
| 매출 | `monthlySales` | 홈택스 연동 목업의 월별 매출 또는 입력 월매출 | 매출 추세, 변동성, 12개월 매출 전망 |
| 비용 | `rent`, `laborCost`, `materialCost`, `totalExpense` | 홈택스 연동 목업 또는 직접 입력 | 고정비, 매출연동 변동비, 현금흐름 |
| 보유 현금 | `currentCash` | 직접 입력 | 시작 현금과 안전자금 위험 |
| 기존 대출 잔액 | `existingDebtBalance` | 직접 입력 | 대환 가능 여부, 기존 상환 스케줄 |
| 기존 월 상환액 | `existingMonthlyPayment` | KB 계좌 연동 목업 또는 직접 입력 | 실제 입력 시 기존 월 상환액 우선 반영 |
| 기존 대출 금리 | `existingLoanInterestRate` | 직접 입력 | 월 상환액이 없을 때 상환액 산정 |
| 기존 대출 잔여 기간 | `existingLoanRemainingMonths` | 직접 입력 | 상환 종료 시점과 만기 잔액 반영 |
| 사업장 정보 | `industryCode`, `areaType` | 직접 입력 | 진단 비교군, 추천 신호, 향후 업종 보정용 |
| 추천 선택 | `sourceType`, `id` | 추천 API 결과를 그대로 전달 | KB 상품/서울시 정책 카탈로그 조건으로 계산 |

현재 KB/홈택스 버튼은 외부 API를 실제 호출하지 않는 데모 목업이다. 홈택스는 월평균 매출, 월지출, 임차료, 인건비, 매입비, 6개월 매출 이력을 채운다. KB는 월평균 매출, 월지출, 월 대출상환액, 카드매출 비중을 채운다.

## 실제 MyData/Open API 연결 시 우선 수집할 값

1. 계좌 잔액: 사업용 계좌의 현재 가용 잔액과 최근 3개월 평균 잔액.
2. 매출 거래: 월별 카드, 현금, 배달 플랫폼 매출과 취소/환불 금액.
3. 지출 거래: 임차료, 인건비, 매입, 공과금, 플랫폼 수수료, 마케팅비, 세금으로 분류한 월별 지출.
4. 대출 정보: 대출별 잔액, 금리, 상환방식, 다음 납부일, 월 납부액, 만기일. 여러 건이면 대출별로 받아 합산한다.
5. 세금 정보: 부가세 및 종합소득세 예상 납부월과 최근 납부액. 현재 엔진의 세금 8% 적립 가정을 실제 일정으로 대체할 핵심 입력이다.
6. 사업 정보: 업종, 사업 개시일, 주소/상권, 상시근로자 수, 매장 면적. 정책 자격 검증과 업종별 비용 벤치마크에 필요하다.

## MVP에서 직접 입력으로 반드시 받을 값

- 최근 3개월 이상 월매출. 6개월 이상이면 추세와 변동성의 신뢰도가 높아진다.
- 월 총지출과 가능하면 임차료, 인건비, 매입비의 분리값.
- 현재 보유 현금.
- 기존 대출 잔액, 월 상환액, 금리, 남은 기간. 대환 추천을 제공하려면 잔액이 필수다.

## 계산 원칙

- 매출은 최근 이력의 추세와 변동성을 사용해 12개월 기준 시나리오를 만든다.
- 몬테카를로는 매출 충격뿐 아니라 변동비와 고정비의 작은 변동도 함께 반영한다.
- 안전자금선은 `고정비 + 해당 월 기존 상환액 + 신규 상환액`으로 매월 다시 계산한다.
- 선택한 KB 상품과 서울시 정책은 추천 API의 식별자를 그대로 넘기고, 시뮬레이션 카탈로그의 조건을 우선 사용한다.
- 카탈로그에 금리/기간이 없는 상품은 MVP 기본 가정으로 계산하며, 결과 경고에 명시한다.

## 아직 남은 고도화 항목

- 대출별 상환방식과 납부일을 MyData에서 받아 여러 건의 상환표를 합산한다.
- 세금 납부월, 지원금 실제 지급 지연, 정책별 한도/자격 조건을 데이터로 반영한다.
- 업종/상권별 비용 벤치마크와 계절성을 매출 시나리오에 연결한다.
- 실제 점포 데이터가 쌓인 뒤 XGBoost 기반 매출 분위수(P5/P50/P95) 예측을 보조 모듈로 추가한다.
